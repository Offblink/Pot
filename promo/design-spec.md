## 1 产品简报

**是什么**：Pot 是一台机器上的 Agent 宿主——你给一句话目标，Planner 把它变成看板上的一张卡；盘上的常驻角色按标签认领、持租约执行、写完回报，**报告即完成**；看板住在浏览器的俯视场景里，人只在想重开时动一下。

**给谁**：已经在用 AI 写代码、写文档，但被「一条对话装不下多线程工作」卡住的独立开发者与小团队。他们要的不是更聪明的聊天框，是**活能干完、状态能看见、失败有记录**。

**核心卖点（各一句）**：

1. **一句话就是一张卡**——目标离开对话上下文，落进 sqlite 的一行，跨轮次、跨进程存活；对话结束不等于工作结束。
2. **分工是数据，不是提示词**——角色有 `canClaim` 标签集、WIP 配额与租约，认领在代码里逐条比对；agent 给自己开权限在代码层没有路径。
3. **报告即完成**——角色写完回报，卡直达 `done`（清租约、holder 留作署名），报告以卡片块自动落回派它的那个会话；人只在想重开时介入。

**本片要立的画面事实（每条都有对应镜头，见 §8）**：聊天里的一句话 → 板上的一张卡 → 俯视场景（正多边形、顶点工位、像素方块 agent） → 标签闸先拒后过 → 满配额自动增殖 → 报告落回会话 → 整块板收成字标。

## 3 数据与音频约束

### 3.1 数据（全虚构 + 采集前冻结）

| 项 | 采用值 | 理由 |
|---|---|---|
| 主指令文案 | `把 README 里过期的地方找出来` | 用户给定的开场句，也是 README「看板怎么跑」里的示例句；不含个人信息 |
| 板上其它卡标题 | 沿用 README 公开示例：`排查上传卡在 99% 的问题` / `给续传章节补中文注释` / `实现断点续传的分片校验` / `给看板加导出 CSV` / `整理发布清单` / `修好托盘菜单字体` + 本片新增 `把 README 里过期的地方找出来` | 这些是产品公开截图里已有的示例任务，无客户名/无个人数据；冻结为固定字符串，不随真实数据库变化 |
| 角色名 | `写手` / `审稿` / `执行者` | 用户指定的通用词，不用真实角色 id |
| 实例编号 | `写手#1` / `执行者#1` / `执行者#2`（mono） | 对应 README 的「一实例一会话、编号 #n」 |
| 状态与错误码（mono 标注） | `role_mismatch` / `wip_full` / `done` / `wip 1/1` → `wip 2/2` | 代码里的错误码就是契约，属于允许的英文代码标识；不新增编造的错误码 |
| 时间戳 / 会话标题 | 相对时间（`刚刚`）或清空 | 避免真实时间与用户名 |
| 禁止出现 | 真实 api key、真实用户名、绝对文件路径、真实模型名、端口号 | 用户给定 |

### 3.2 音频

- **无旁白、无配音**。字幕是唯一语言通道（C1：不留哑巴段落，品牌收尾镜头除外）。
- **BGM 120 BPM**（可由 60/240 BPM 的曲子折半/加倍满足）：六段边界 120 / 300 / 540 / 690 / 915f 分别落在第 8 / 20 / 36 / 46 / 61 拍，全部整拍。选曲在阶段 6 定，类型按 S1「强鼓点 tech-house 底」，必须垫进成片试听后再定。
- **SFX 词汇**（阶段 6 逐条钉帧，此处只定意图）：打字随字键盘拟音（S1）、卡落地 `impact` + 底噪 `whoosh`（S2）、拒绝一记 `thud`（S3 342f）、四宫格连发 `pop` 阶梯递减 + 间隔加速（S4）、完成一记真实开关拟音 + 纸张（S5 690f）、蒸发 `whoosh` + 收尾单点 `sparkle`（S6）。
- 交付两版：带 BGM / 无 BGM（保留 SFX），靠 `bgm` inputProp 从同一时间线渲出（阶段 7）。

## 5 动效性格 tokens

**品牌定位**：能量轴 **中（4/10）**、调性轴 **理性偏严肃（工程感，6.5/10）**。
依据：产品视觉是锐利几何 + 中性灰 + 一套克制的绿（Q 轴证据：锐利几何 → 工程感）；用户口述「理性工程感」覆盖视觉推断。
预设起点：**专业信赖（~21f，`bezier(0,0,0.2,1)`，过冲 1.0，squash 0）**；按用户给的例外追加「卡片是有实体物件的」一条微过冲。

| 物件类 | 时长 | 缓动 | 过冲 | squash | 说明 |
|---|---|---|---|---|---|
| 卡片（飞行/落地/归位） | 21f（主）/ 11f（落定） | 入场 `--ease-out-expo`，落定 `--ease-spring` | **1.02** | 0.985（仅落地 2f） | 用户给定：卡是实体物件；但只此一类，别的物件不许弹 |
| 文字 / 字幕 / 色块 | 8f 入场、5f 出场，逐词 0.7×句窗 | `--ease-smooth` | 无 | 0 | 字幕不做位移花活，只做逐词加深 |
| chip / 标签 / 徽标 | 11f | `--ease-spring` | 1.02 | 0 | outBack 的「发牌落桌」手感来自卡（doc-park 参数），但幅度压到 1.02 |
| 像素方块 agent | 6f 位移 + 明度跳变 1 档 | `--ease-out-expo` 位移 / 步进 明度 | 无 | **0** | 用户给定：只做位移与明度跳跃，**不做缩放弹跳** |
| 状态切换（红/绿点、勾、划掉、`done`） | 4.5f / 勾 7f / 划掉 12f | linear 或 `--ease-smooth` | 无 | 0 | 用 Pot 的 `--t-fast` 语言，读作「代码判定的结果」而不是动画 |
| 相机 | 21f 微动 / 102f 拉升 / 24f 拉回 / 6f 急推 | 卡上参数优先：crane `bezier(0.2,0,0.25,1)`；急推 ease-in(cubic)；拉回 `--ease-smooth` | 拉升末端 ≤3° | — | 相机是「持镜人」，全片只用一个方向的揭示；判例赢预设 |
| 蒸发（S6） | 每层 14f，层间 4f | ease-in(quad) | 无 | 0 | 离场要加速，ease-out 会读作「飘走」 |

**三条硬自检（写死进阶段 5）**：

1. 同一动效手法全片只当一次主角：打字（S1）/ 嵌入（S2）/ 俯仰+升起揭示（S2 相机）/ 急推撞停（S3）/ 2×2 硬切并行（S4）/ 让位+慢发牌（S5）/ 层剥蒸发（S6）——互不重复。
2. **整画面/相机层冲击（slam）全片 ≤3**：本片用 **2 处**——S3 `342f`（撞停 6f 急推 + 14px 震屏衰减）、S5 `690f`（顿帧 2f + 3px 全画面微震）。其余拍点只动元素层（R4）。
3. hold/rest 预算先划后排：每段尾 ≥15f 静止（0.5s），关键信息落定 ≥30f（1s），品牌字标 93f（3.1s，≥1.2s 要求）。

## 6 三个文字方向 + 选定理由

### 方向 A「第二人称陈述」（选定）
每句一个动词，说的都是观众眼前刚发生的事：`你只给它一句话` → `它落在板上` → `谁认领，由标签决定` → `配额满了，就多开一个` → `报告交回，卡就完成了` → `一台机器。一块板。`
优点：不需要铺垫，无旁白也读得通；句式短，60px 字幕一行放得下；把「对立」（对话 vs 板）留给画面而不是文案。

### 方向 B「工程断言」
用状态与错误码说话：`todo → doing`、`role_mismatch`、`wip 1/1 → 2/2`、`report → done`。
优点：工程感最强，和 mono tokens 同源，最贴「理性」调性。
缺点：`role_mismatch` 对非开发者是噪音；字幕变成日志，观众要「读代码」而不是「看结论」；且与 S3 画面里已经出现的 mono 标注重复。

### 方向 C「对立否定」
`不是更聪明的聊天框，是一块板。`
优点：直接承载主题句，气势足。
缺点：全片都在否定，口吻变批判；更要命的是 S3 本身是「先红拒再绿过」的**先否后肯**句式，字幕再用否定句式，等于同一句式在 22 秒里出现三遍（P4 去重精神）。

### 选定：A，取 B 的一小块
理由：主题句的对立交给画面（会话 vs 看板），字幕只做**陈述**；工程感降级成画面里的 mono 小标注（`写手#1`、`wip 1/1`、`role_mismatch`、`done`）——B 的优点保留、阅读门槛下放；C 与 S3 句式撞车，弃。

### 6.1 最终文案逐字稿（S1–S6，无占位符）

## 7 styleframe 处理：跳过（附理由）

**决定：本阶段不产出 HTML/CSS styleframe。**

理由（三条，均为可复核约束，不是省事）：

1. **本卡明令「不要截图」**：styleframe 的验收方式是 Playwright 截静态帧看字体/材质/信息密度（pipeline 阶段 1 第 4 步）。本卡禁止截图，做了也无法验收，属于产出无法闭环的中间物。
2. **视觉方向不由我自由发挥**：全片色板/字体/字号/圆角/阴影/缓动全部锁定在 `web/style.css` 的 `:root`（§4 逐项列了行号），没有需要「比稿」的视觉变量；画面主体又是**必须真实截图**的页面。styleframe 能替观众回答的问题，只剩「这套 token 在 1080p 里读不读得清」。
3. **「读不读得清」已由硬阈值取代**：Q11 给出 60/40/32px 三档有效字高与「缩到 480px 宽还读得清」的验收法，比 styleframe 的目测更严；执行位置也更正确——阶段 5 每镜的 `npx remotion still` 验收帧（每镜写死 2 个帧号）直接量最终像素。

**补偿动作**（把 styleframe 的风险前移消化）：§4.3 给出影像字阶 + 三档阈值；§8 给每镜写死验收帧号；S2 的 3.0x 特写必须在阶段 4 走 Q2 高清栅格化（全页 2x + 关键行 4x），否则字会糊——这条列进 §11 未决项。

## 12 附录 A：对用户已给创作方向的修改与理由

用户给的六段结构、主题句、tokens 与硬规则**全部保留**。以下 10 处是细化或替换（每一处都给了可复核依据，卡名/变体均在 `library.json` 校验过）。

| # | 用户给的 | 实际采用 | 理由 |
|---|---|---|---|
| 1 | S1 打字：`typewriter-moves` 或 `type-rhythm-sync`，备选 `glass-pill-dictation-typing` | `glass-pill-dictation-typing` | ① `typewriter-moves` 库内只有 `error-retype` 一个变体，语法是「先打平庸词 → 退格 → 改成卖点」——这会把 S1 变成「先错后对」，与 S3 的「先红拒再绿过」重复同一句式，全片出现两次「先否后肯」读作套路；② 它 160f，超出 S1 的 120f 预算，压到 120f 会削掉「犹豫」这一命门时值；③ `type-rhythm-sync` 两式分别绑鼓点（高能）与旁白逐词（本片无旁白），都不适合开场；④ glass-pill 的「光标先行 + 匀速打字 + 光随输入退去」是一条完整动作弧，100f 正好吃进 120f，且它是全片最安静的一拍 |

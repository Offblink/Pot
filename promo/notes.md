# promo 施工记录（阶段 5A / 5B）

> 这份文件只记**对设计定案与镜头卡的适配性改动**及其理由。文案一个字都没改；
> 要改文案请先看 `design-spec.md §6.1` 的逐字稿。

## 工程骨架

- `package.json` / `tsconfig.json` 取自 `data/skills/video-shotcraft/template/`（只借骨架）。
- `npm install` 在本机失败过一次：`esbuild` postinstall 校验到二进制版本不符
  （`Expected "0.28.1" but got "0.21.5"`，npm 缓存里是模板那份）。
  处理：直接复用模板已验证过的 `node_modules/`（同版本 remotion 4.0.484 / react 19.2.7），
  再把 `template/node_modules/.remotion/chrome-headless-shell/` 复制到 `promo/` 下。
- **`npx remotion still` 在本机必须带 `--browser-executable`**：缓存的 headless shell
  在本机直接启动会失败（`Failed to launch the browser process`），系统 Chrome 可以：
  `--browser-executable="C:\Program Files\Google\Chrome\Application\chrome.exe"`。
  `scripts/qa-stills.bat` 已经把这一条写死。

## 静态资源的两个坑（都写进了 `src/lib/staticUrl.ts` 与 `src/assets.ts`）

1. 本机 `window.remotion_staticBase === '/public'`，而 `staticFile('textures/x.png')`
   会把拼好的 `/public/...` 再判一次「已带前缀」并抛错（模板工程首帧同样报这个，
   `template/warm.log` 的 `EXIT=1` 就是它）。手工拼又会变成 `/public/public/...` 404。
2. 采集产物的文件名里带 `@`（`scene-full-zh@2x.png`），URL 里被二次编码成 `%2540`。
   → `scripts/sanitize-textures.py` 生成 `-2x` 副本（原文件保留，采集 README 仍按 `@2x` 引用）；
   → 纹理改成 **webpack import**（`src/assets.ts`），不走 staticFile。

## S1 · glass-pill-dictation-typing

保留的命门：定宽不伸缩、`scale 1.25→1` 20f（snappy）、opacity 前 2f 满、落位前 6px→0 景深、
光标先行、匀速 3f/字、光随打字退去（同窗）。

适配：
- 材质从「玻璃 + 暖光 + 5 根声波竖条」换成 Pot 的 `--surface/--border/--shadow-card` +
  `--accent-glow` 绿；撤声波按钮（Pot 的输入框没有语音态）。
- 胶囊尺寸 = **真实输入槽位** 1000×57（`layout.json` 的 `#input-area` 内槽），不是 1240×132：
  覆层必须与真实槽位同尺寸同位置，否则读作贴片。
- 打字窗口 26–80f（18 字 × 3f），落位 6–26f —— 与 `plan.json` 的 beats 对齐。
- 相机 1.62 倍、对准点落在输入条（cy 746.7）：让消息区留在上半屏、输入条在下三分之一，
  字幕移到**顶部**（`Caption placement="top"`），否则字幕会压在输入条上。

## S2 · row-embed + crane-rise-reveal

保留的命门：落点是真实槽位、`rotateX 16°→0` 收平、`bezier(.5,0,.8,.75)` 末段带速度砸入、
press 回弹、底边 2px 强调色缝只闪一次且裁在圆角里；相机的 scale 3.0→1.0 / 102f /
一条 `bezier(0.2,0,0.25,1)` 共用给对准点与 scale、满幅后不再补推、静止 ≥30f。

适配：
- **空板 backplate 用 `scene-full-empty`，在 122–132f 与满板纹理交叉淡化**：两张都是真截图，
  这样 S2 开头那格真的是空的，卡落进去才不是"补丁"。
- 主角卡是 React 真文字覆层（真实卡行只有 36px 高，放大 3.2 倍后需要它自己动）。
- 逐行洗光改成 Pot 的 `--accent` 绿，触发帧仍按「视野上缘越过该行顶边」逐帧解。

## S3 · crash-zoom-punch（撞停款）

保留的命门：急推 6f `ease-in(cubic)` 1→2.5、撞停**不回弹**、`14px·e^(−t/1.8)` 6f 收干、
前 hold ≥30f、后 hold ≥45f、运动模糊只包急推段。

适配：
- **不做整幅负片/集中线**（卡里 C 式的可选款）：与 Pot 的亮场工程嗓音冲突，
  代价是 slam 重音全部押在顿帧 2f + 震屏 + 一次红 chip 翻转上。这是全片第 1 处 slam。
- 收尾停在 zoom 1.55（不回 1.0）：回 1.0 时整块板只占画宽 23%，"卡换区""方块亮起"都退化。
- **被拒的角色改成「审稿」而不是「写手」**：采集数据里 写手.canClaim = [docs] 而卡标签也是
  docs（相交，不该被拒）；让 审稿（canClaim [review]）去撞 docs 才是画面与数据自洽的那次
  `role_mismatch`。文案本身一个字没改。

## S4 · quad-split-parallel-scenes

卡片配方是**错拍表**（相邻重事件 3–6f，任一帧不得两路同时发生重事件），不是 2×2 的外形。
按 5B 卡的要求落到 Pot 自己的空间：俯视场景里四条轨道同时前进（写手推卡 / 审稿勾清单 /
exec#1 耗时跳数 / exec#2 增殖 + wip 读数）。本镜自己的错拍表：
`546 TL · 552 TR · 556 BL · 560 TL · 566 TR · 570 BL · 574 TL · 580 TR · 584 BL · 588 BR 红 · 600 BR exec#2 · 608 ×2 · 616 wip 2/2`

把"并行"收束回"一块板"这个主语。

### 顺带修掉的一个隐藏 bug
`chip(text, …)` 这个 helper 把 `text` 当参数收下却**从不渲染**（调用处是 `<span style={chip(…)} />`，没有 children），
所以校验条上一直是两个**空药丸**——`out/qa/S3-a.png` 里那个"淡红圆圈"就是它。
现在改成 `chipStyle(fg, bg, border, mono)` 只返回样式，文字由 children 提供。

### 一处 S3 之外的必要改动（已在 report 里请 Planner 复核）
`src/PotPromo.tsx` 的字幕层：把 S3 那句放到**顶部，bottom=126**。
理由：收尾要把工位（屏幕 15–114）与整块板（391–1034）同时收进画，两者之间只有 114–391 这块空地板；
字幕若留在底部 96（884–984）就会压住板的下四行。改动只影响 S3 一条 cue；
S1 仍是 top/96、其余仍是 bottom/96（映射已逐条核过）。

### 自检脚本
`scripts/check-s3.py`：从 `src/layout.json` 取板/行/工位矩形，从 `S3.tsx` 读相机常数，

## S1 + S6 修复（卡 p-878fbc68）

### S1 取景与覆层
| 项 | 旧 | 新 |
|---|---|---|
| `CY` | 746.7 | **800** |
| `zoom` | 1.62 / 1.64 | **1.50 / 1.52** |
| 覆层几何 | `CHAT_INPUT_SLOT`（293 / 1009 / 1000×57，采集期手填的近似值） | **实测 `SLOT = 294 / 998 / 1460×61`** |

- 可见页面 y **440..1160**、x **153..1433**：输入区 998..1059 → 屏幕 **837..928.5**，下方留 **151px**。
- 覆层宽度取 1460（到页面 1754）而不是真实框宽 1459 —— zoom 1.50 的可见右缘是页面 1433，
  真实框右缘 1753 本来就在画外；覆层必须盖过去，否则会在画面里露出一道**竖直接缝**（右边残留半截真输入框）。
- 覆层高度按实测 998..1059（高 61）：前一版用 1009/57 会在屏幕 837（真框上沿）与 939（覆层下沿）各留一条横线，读作"双边框"。
- 打字文字 38 页面 px × 1.50 = **57 屏幕 px**（Q11 的可读线是 36px），光标在字后；底图那块被 `C.surface` 完全盖掉，不存在两层字打架。

### S6 两处
1. **重复字幕**：`PotPromo.tsx` 的 `Captions` 跳过 `c.from >= SHOT('S6').from`。
   `timeline.ts` 里的 caption 字符串是事实源，没动；S6 自己的 tail（`TAIL_IN = 1135`）保留。
   于是「一台机器。一块板。」全片只出现 **1 次**。
2. **暗场灰块 / 灰边带**：根因不是"bgDark 没到 1"，而是**合成次序**——
   六个语义裁片是**不透明**的，它们把底层"正在变暗的母版"完全挡住了，
   所以只有"已蒸发的区域"才显出变暗的母版 ⇒ 必然出现矩形色差。
   改法是换成四层：
   ```
   ① DARK 满幅不透明（底）
   ② 整页纹理满幅不透明（亮场舞台，与裁片同一份像素）
   ③ 六层裁片：只负责运动（错峰 + 方向位移 + 蒸发模糊）
   ④ DARK 满幅、opacity = bgDark，945→985 走到 1（上）
   ⑤ 幸存者按钮 / 字标 / tail
   ```
   裁片消失时露出的是 ② 同位置的像素 → 零色差；压暗完全由 ④ 承担 → 全场均匀。

## S1 返工（卡 p-30e71501）

上一版（CY 800 / zoom 1.50）把三件事同时做坏了，本卡逐一修：

| 病灶 | 根因 | 改法 |
|---|---|---|
| 输入条右缘被切出画面 | 可见页宽 = 1920/1.5 = **1280 < 输入框宽 1459** | **选方案 A 的前半条：zoom 1.15**（可见页宽 1670 ≥ 1600）；输入条屏幕 1679 宽，右留 **215.7px** |
| 底部一条水平色带 | 可见下缘 1160 > 页高 1080 → 露出容器底；且页面底部 21px 是**白色**（输入区页脚），容器是 `--bg` | **把页面 y≥1062（白色页脚起点）整段盖成 `--bg`**，画面下缘与页面其余部分同色 |
| 3/4 空灰底 + 左侧硬边 | 侧栏进了画（可见左缘 153 < 272） | **cx 1106.78 让画面左缘正好落在页面 x=272**（侧栏右缘）：侧栏整块不进画，硬边消失 |

现在的相机与构图（由源码常数算出，`scripts/check-s1.py` 复核）：

```
zoom 1.15 / cx 1106.78 / cy 815.4     可见页面 x 272..1942、y 384..1323
输入条屏幕 x 25.3..1704.3  y 750..820.1
边距：左 25.3  右 215.7  上 750.0  下 259.9
打字文字 38 页面 px × 1.15 = 43.7 屏幕 px（≥34）
```

配套三层处理：
1. **顶部遮罩 240px，不透明到 70%（168px）** —— 页面 y342..478 那条报告块（屏幕 −4..154）被整块吃掉，顶边不会出现"半张卡"。
2. **底部遮罩**：从页面 y=1062（屏幕 823.6）盖到画面底，颜色 `--bg`。
3. **会话里最后一条消息**：`chat-report` **真实切片**（392×137 页面 px）放在页面 (293, 754.5) = 屏幕 y 470..627，输入框上方正好 114px。它是页面坐标里的元素，跟着相机一起动。

字幕：`PotPromo.tsx` 的 `CAPTION_LAYOUT.S1` 从 `top 96` 改到 **`top 300`**，与输入框形成"上句下框"；只影响 S1 自己的 cue。

### 为什么左边界只留 25.3px
输入框左缘在页面 x=294，会话列从 272 开始——两者只差 22px。要在左边留 120px 就必须把页面 x≤189 也框进来，那里正是 272 宽的白色侧栏 + 一条 `--border` 竖线，即本卡点名要消掉的"半个侧栏"。所以选「侧栏完全出画、左留 25px」，把 120px 的呼吸需求放在**右侧**（215.7px）。

### 自检

## S3 接缝修复（卡 p-864cf327）

**问题**：S2 收尾 `zoom 1.45 / cy 431`（内容占画高 96.7%），S3 起手还是原始 `zoom 1.0 / cy 540`
→ 帧 300 突然变成"整页缩小 + 左上冒侧栏 + 四周死白"。

**改法（变量从 S2 导出，不抄数值）**：在 `S2.tsx` **新增** `export const S2_EXIT_CAM`，
它用 CAM 里已有的末两键（246 @1.45 → 300 @1.45×1.018）按同一条线性插值取出 **299 帧**的真实机位；
`S3.tsx` `import { S2_EXIT_CAM }` 并把 CAM 前两键（300 / PUNCH）改成 `S2_EXIT_CAM.cx/cy/zoom`。
S2 的任何数值一个都没改（只新增 export）。

**为什么不是卡面写的 1.45**：S2 在自己 Sequence 里只渲染到 local 179 = 绝对帧 **299**，
而 CAM 末键是 300 —— 299 帧的 zoom 其实是 1.45×(1+0.018×53/54) = **1.4756**。
从 1.45 起手会让板跳 1.8%（≈11px），超出卡里给的 1px 容差。导出真实末帧机位后实测 **Δ = 0px**。

**撞停幅度**：`CLOSE_ZOOM 2.0 → 2.15`（卡给区间 2.0–2.15 的上限）。
起手 1.4756 → 2.15 是 **1.457 倍**急推；若仍用 2.0 只有 1.355 倍，明显偏软。
2.15 下可见高 502 vs 板 429 → 上下各余 36.7 页面 px = **78.9 屏幕 px**，减震屏 14px 仍安全。
**前 hold 未缩短**（仍 36f / 帧 300–336）：缩短只让急推提前、不会加大幅度，而它是命门之一。

**撞停帧的 cy 必须回 540**：起手 cy 是 431（S2 的包围盒中心），但 2.15x 下若 cy 仍 431，
可见带是 180..682，板底 754.5 会被切。所以 336→342 这 6f 里 cx/cy 从 431 回到 `BOARD_CENTER.y`
（板心），zoom 同步推到 2.15 —— 读作"推近并咬住板心"。
